# Reasoning corpus: format reference

What each record in the corpus contains, what every field in `y_steps` /
`b_steps` means, and the exact formulas behind the numbers in the trace.
Generated by `v2/llm_reasoning_corpus.py`.

## Files

| What | Where |
|---|---|
| Input PSMs | `/disk/raptor-array/mshab008/msbenchmarking/hardness_index_0/filtered_spectra/hardness_index_0.parquet` |
| Full corpus | `/disk/raptor-array/apali007/msbenchmarking/hardness_index_0/reasoning_corpus/hardness_index_0.jsonl` |

Format: JSON Lines, one record per line.

```python
import json
with open(path) as f:
    for line in f:
        record = json.loads(line)
```

## Record fields

| Field | Meaning |
|---|---|
| `id` | PSM id from the parquet (`PSMId`) |
| `dataset` | PXD accession |
| `spectrum` | **Model input**: precursor m/z and charge, fixed and variable mods allowed, fragment tolerance, peak list (sorted by m/z, duplicates removed, raw intensities) |
| `reasoning_trace` | **Model target**: intro → y ladder lines → b ladder lines → "final sequence ..." |
| `peptide` | Label with mods removed: `KEMQPTHPIR` |
| `modified_peptide` | Label with variable mods: `KEM[15.9949]QPTHPIR` (fixed C+57 not written) |
| `y_steps` / `b_steps` | Every number behind the ladder text (for verification and stats, not training) |

Each line in a ladder section of `reasoning_trace` corresponds to one step,
in the same order. A ladder with no ions gets "No y ions were found in this
spectrum." The precursor conversion is explained once: in the y ladder if
it used the precursor, otherwise in the b ladder.

## Steps

There are four kinds of step; `method` tells which.

| `method` | What it is | Residue named? |
|---|---|---|
| `"first"` | y1 or b1: residue from the ion alone | yes, the terminal residue |
| `"diff"` | previous ion (i−1) also observed: residue = mass difference | yes, residue i |
| `null` | **gap**: previous ion missing; listed so the next ion can use it | no |
| `"precursor"` | full-length ion never exists, so the last residue comes from the precursor mass (only if ion n−1 was observed) | yes, the last residue |

A missing ion has no step at all.

### Ion step fields

Always present:

| Field | Meaning |
|---|---|
| `ion` | `y3` = last 3 residues, `b3` = first 3 |
| `mz` | observed peak m/z |
| `theoretical_mz` | calculated m/z for this ion at **this charge and loss** (what the peak matched) |
| `intensity` | observed intensity (raw) |
| `charge` | fragment charge, 1 to precursor charge |
| `loss` | `null`, `"H2O"` or `"NH3"` |
| `ion_mass` | the peak as a **1+, intact** ion; what the ladder subtracts |
| `method` | see above |

Only sometimes present:

| Field | When | Meaning |
|---|---|---|
| `singly_charged_mass` | charge > 1 | mz converted to 1+, **before** adding back the loss |
| `ptms` | first observed ion containing a PTM | `[[name, mass, count]]`, e.g. `[["oxidation", 15.99492, 1]]` |
| `prev_ion`, `prev_mass` | `"diff"` | previous ion and its `ion_mass` |
| `residue_mass`, `residue`, `pos` | `"first"`, `"diff"` | residue mass, label token (`M[15.9949]`), position |

### Precursor step fields

No `ion`, `mz` or `charge`. Fields: `method: "precursor"`, `ion_type`,
`prev_ion`, `prev_mass` (ion n−1), `precursor_mz`, `precursor_charge`,
`neutral_mass`, `residue_mass`, `residue`, `pos`.

## Formulas

Constants (`constants.py`): p = 1.007276467, H2O = 18.01056467, NH3 = 17.026549105.
Residue masses = `AA_MASSES` + fixed mod (from metadata JSON) + variable mods (`VARIABLE_MODS`).

```
theoretical  b_i = (sum residues + z·p) / z
             y_i = (sum residues + H2O + z·p) / z
             with loss: − loss / z

singly_charged_mass = mz·z − (z−1)·p
ion_mass            = singly_charged_mass + loss        (= mz when z=1, no loss)

first  y1:  residue_mass = ion_mass − H2O − p
first  b1:  residue_mass = ion_mass − p
diff:       residue_mass = ion_mass − prev_mass

neutral_mass = precursor_mz·z − z·p
precursor y: residue_mass = neutral_mass − prev_mass + p
precursor b: residue_mass = neutral_mass − H2O − prev_mass + p
```

+p because `prev_mass` is a protonated (1+) mass; −H2O for b because b ions
lack the C-terminal water.

PTMs are not added to `ion_mass`: they are already in the observed `mz`.
They only enter `theoretical_mz` (through the residue masses) and the trace
text (explaining a modified residue mass).

## Examples

`KEM[15.9949]QPTHPIR`, precursor 626.82719, 2+ (PXD024190):

```
y1  "first"   175.11913 − 18.01056 − 1.00728 = 156.10128      → R (pos 10)
y3  null      gap, y2 missing
y4  "diff"    522.31506 − 385.25592 = 137.05914               → H (pos 7)
y8  "diff"    ptms [oxidation], 147.03571                     → M[15.9949] (pos 3)
precursor     626.82719×2 − 2×1.00728 = 1251.63983
              1251.63983 − 1124.55200 + 1.00728 = 128.09510   → K (pos 1)
```

A 3+ ion with an NH3 loss:

```json
{"ion": "b5", "mz": 182.06876, "theoretical_mz": 182.08604, "charge": 3, "loss": "NH3",
 "singly_charged_mass": 544.19172, "ion_mass": 561.21826, "ptms": [["oxidation", 15.99492, 1]], "method": null}
```
```
182.06876 × 3 − 2 × 1.00728 = 544.19172   singly_charged_mass
544.19172 + 17.02655         = 561.21826   ion_mass
```

## Matching (`match_ions`)

1. Theoretical b1..b(n−1) and y1..y(n−1) for every charge 1 to precursor
   charge, each intact and with H2O and NH3 losses.
2. Every (ion, peak) pair within the fragment tolerance is a candidate.
3. Greedy: intact before loss, then lower charge, then smaller error, then
   higher intensity. Each peak and each (ion, charge, loss) used once.
4. Per ladder position one peak is kept: intact before loss, then lowest charge.

Unmatched peaks are noise and are not mentioned in the trace.

## Things to remember

- `pos` always counts from the **N-terminus**, for both ladders: y1 has
  pos = n, b1 has pos = 1.
- Residues come from the label. A residue is only *named* where a mass
  supports it, but the name is the label residue at that position.
- A PTM is named on the first observed ion containing it, which can be a
  gap step.
- Steps are saved rounded to 5 decimals; calculations use full precision.
  Recomputing from saved numbers needs a tolerance of about 2e-5.
- Expected residue mass error for a diff step: up to about
  tolerance × (z_i + z_prev).
- PXD053477 uses a 0.5 Da fragment tolerance (metadata JSON); about 18% of
  its matched ions are > 0.02 Da off, likely chance matches. Open question.
- Hardness 1–5 are not supported yet (new PTMs, mod format in metadata JSON,
  low-resolution tolerances).
